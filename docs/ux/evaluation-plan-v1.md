# ARA UX evaluation plan v1

## Goals

Validate comprehension, task completion, accessibility and recovery for the approved screen contracts—not educational effectiveness.

## Participants/roles for formative evaluation

- self-directed learners, including workers studying in short sessions;
- course authors/teachers/tutors with no database expertise;
- reviewers/researchers;
- accessibility users and specialists;
- institutional administrators.

No participant recruitment or data collection is authorized by this plan; execution requires an approved protocol.

## Priority tasks

1. Download a course and resume offline.
2. Explain current version/profile/offline state.
3. Change a high-impact parameter and identify whether it creates runtime, content or composition change.
4. Follow GPT-authored artifacts, comment on one card and request scoped repair.
5. Distinguish reference, copy and fork.
6. Audit without editing; authorize and verify repair.
7. Publish privately and identify audience/version/withdrawal.
8. Resolve an offline authoring conflict without losing local work.
9. Build a minimal research protocol and explain event/measure/construct differences.
10. Change a workspace role without creating a global administrator.

## Methods

- moderated task walkthroughs;
- think-aloud with caution for accessibility/cognitive burden;
- comprehension questions after consequential decisions;
- keyboard/screen-reader and zoom/reflow inspection;
- physical Galaxy A07-class device performance/usability walkthrough;
- heuristic/accessibility expert review;
- locale review for en, pt-BR and pt-PT;
- failure injection using static/prototype states.

## Success criteria

- critical tasks complete without moderator correction;
- users can state target/version/consequence before publish/delete/fork/parameter derivation;
- no essential action requires drag/hover/vision/color;
- errors preserve entered work and expose recovery;
- participants distinguish offline-local from synchronized/published state;
- authors can locate comments/findings and understand audit vs repair;
- researchers distinguish events, measures and constructs;
- no critical WCAG 2.2 AA blocker;
- all findings trace to screen/state and return to #6/#7 if semantics/architecture are missing.

## Evidence package

Preserve prototype version, task script, environment, participant governance, findings, severity, recordings/notes policy, locale/device/AT, decisions and unresolved risks.
